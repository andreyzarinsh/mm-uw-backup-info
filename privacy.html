Data handling — MM UW Backup rclone

Updated 26 September 2026. This notice describes the owner's personal backup application.

Purpose and data

The application transfers project recovery archives selected by the owner from the owner's computer to the owner's Google Drive. Archives may contain source code, project documents, database exports and application configuration. File metadata and checksums are used to verify transfers and manage retention.

Google permission

The application requests drive.file access to the specific Drive files used with this application. Authorization tokens and the OAuth client configuration are stored locally for scheduled backups. This application does not request access to Gmail, contacts or calendars.

Storage and access

Backup archives are stored in the owner's Google Drive under the owner's access controls. Publishing this informational page does not publish backup archives. The configured workflow does not intentionally sell backup data, use it for advertising or send it to an AI model for training. Google processes stored files according to its applicable service terms.

Retention and control

The configured retention target is four weekly and three monthly points, counting overlaps once, within a 1 TB backup-folder limit. Old backup files are removed only after verifying a replacement and preserving dependencies of retained points. Incomplete backups may be retained while their recovery coverage is reviewed.

The owner can stop the backup schedule, revoke the application's Google Account connection, or remove stored archives from Google Drive. Revoking authorization stops future access; it does not automatically erase existing backups.

Questions

This is a personal, single-owner utility. The support address for the application is displayed on Google's authorization screen.
